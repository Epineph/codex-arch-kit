# Repository-maintenance experiment 1

This directory is a disposable learning experiment. Read START-HERE.md and
.runs/plan.json before doing work. Follow existing higher-priority instructions.

## Scope

- Edit only candidate/<name> entries listed in .runs/plan.json.
- Read fixtures, job instructions and verification code for context.
- Do not modify fixtures, lab.py, verify_examples.py, this file, editor settings,
  job instructions, or saved baselines/snapshots to make a check pass.
- Do not create, rename, merge, or delete target files in this first experiment.
- Do not install packages, change machine settings, commit, or push.
- These are workflow instructions, not an operating-system security boundary.

## Workflow

Read the selected job files under jobs/. Present the requested plan first.
Work on one selected job at a time, in its numeric order. Stop after each job
for human review. Job 3 needs proposal approval before edits.
Use the controller's checkpoint command before each editing job.
Run checks and report failures honestly; never describe missing tools as passed.
Only execute the supplied example programs and named validation tools. Do not
extend this execution permission to unrelated real-world scripts.

## Style

Use two-space indentation, descriptive names, concise explanatory comments and
clear help. Use function name() in Bash when a function is justified. Prefer
lines of at most 81 characters. Do not add a function merely to satisfy style.
Avoid dependency additions, speculative features, and code shortening for its
own sake. Preserve exit codes, output contracts, argument behaviour, and order.
Formatter configuration is provided in .editorconfig and pyproject.toml.
